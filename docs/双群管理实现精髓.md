# 双群管理实现精髓

## 核心思想

将 **被管理群**（图片审核的目标群）与 **管理群**（接收违规通知、执行管理命令的群）解耦，实现"一个管理员管理多个群"的集中管控模式。

---

## 1. 配置模型 — 群对群解耦

```yaml
group_settings:
  - group_id: "123"          # 被管理群
    manage_group_id: "456"   # 管理群
    ...
  - group_id: "789"
    manage_group_id: "456"   # 同一管理群可管多个群
```

每个被管理群绑定一个管理群，N:1 关系。

---

## 2. 消息路由 — 被管理群触发审核

`main.py:on_message()` 流程：

```
所有群消息 → 只处理被管理群(已配置 group_id) → 提取图片 → 审核 → 发现违规
→ 在被管理群执行：撤回 + 禁言
→ 向关联的管理群发送：合并转发通知(含证据图)
```

关键代码：`ConfigManager.is_group_enabled()` 判断消息来源是否为被管理群。

---

## 3. 命令隔离 — 管理群接收指令

所有管理命令（`/查询违规`、`/审核状态`、`/添加白名单` 等）**只能在管理群中执行**，通过 `ConfigManager.is_manage_group()` 检查：

```python
if not self._config_manager.is_manage_group(group_id):
    return  # 不是管理群，忽略命令
```

被管理群的普通成员完全感知不到管理命令的存在。

---

## 4. 反向关联 — 管理群操作多个被管理群

`ConfigManager.get_group_ids_by_manage_group(manage_group_id)` 实现 **根据管理群 ID 反向查找所有被管理群 ID**，用于跨群操作：

- `/删除违规`：遍历管理群下的所有被管理群，逐个删除违规记录
- 支持一个管理群管理多个被管理群，具备横向扩展能力

---

## 5. 违规通知 — 跨群合并转发

`ViolationHandler._notify_manage_group()` 使用 QQ 合并转发消息机制：

1. 从被管理群下载违规图片（本地存证）
2. 构造违规信息节点（含昵称、QQ号、风险等级、处理措施）
3. 构造违规图片节点
4. 调用 `send_group_forward_msg` 发送合并转发到管理群

管理员/群主在被管理群违规只通知、不处罚（`is_admin` 判断）。

---

## 6. 智能审查模式 — 时间维度上的管理增强

非严格意义上的"双群"，但扩展了管理维度：

- **强制审查时间段**（如夜间 `23:00-09:00`）：始终开启审查
- **管理员在线检测**：管理发言后 x 分钟内关闭审查（减少打扰），超时未发言自动开启
- 适用于"管理在时不管，管理不在时自动补漏"的场景

---

## 总结

| 维度 | 被管理群 | 管理群 |
|------|---------|--------|
| 角色 | 图片审核执行地 | 违规通知接收、管理命令执行地 |
| 消息处理 | 审核所有图片 | 处理 `/` 命令 |
| 违规动作 | 撤回 + 禁言 | 接收合并转发通知（含证据） |
| 管理员违规 | 不处罚，仅通知管理群 | — |
| 配置方式 | `group_id` | `manage_group_id` |

**精髓一句话：被管理群只管"干活"（审核+处罚），管理群只管"看报告+下指令"，二者通过配置绑定，实现集中化管理。**
