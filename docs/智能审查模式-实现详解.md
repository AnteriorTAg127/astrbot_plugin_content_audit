# 智能审查模式 — 群主/管理员在线自动暂停审核

## 概述

智能审查模式是插件的一项核心功能，它允许插件根据**管理员是否在线**自动决定是否对图片进行审查。当管理员在群内活跃时，审查自动暂停以避免打扰；当管理员离开或长时间未发言时，审查自动恢复以填补监管空缺。

## 设计哲学

### 核心思路：被动式在线推断

该功能不依赖平台提供的"在线状态"API（不同平台差异大、可靠性低、权限要求高），而是采用**被动式推断**策略：

- **"在线"的定义**：管理员在 **N 分钟内发送过消息**，即视为"在线"
- **"不在线"的定义**：管理员连续 **N 分钟未发送任何消息**，即视为"不在线"
- **推断依据**：仅依赖每条消息的 `sender_id` 和 `role` 字段，零额外 API 调用

### 安全优先

整个决策链路采用**安全优先**（fail-safe）设计：

| 场景 | 行为 | 理由 |
|------|------|------|
| 从未记录过管理员发言 | 开启审查 | 宁可误判，不可漏判 |
| 无法获取管理员身份 | 开启审查 | 同上 |
| 配置缺失或错误 | 开启审查 | 同上 |
| 异常崩溃 | 开启审查 | `should_enable_censor` 返回 `(True, ...)` |

### AdminManager — 管理员检测与时间追踪

文件：`handlers/admin_manager.py`

核心数据结构：

```python
class AdminManager:
    def __init__(self):
        # 管理员列表缓存 {group_id: {"admins": set[str], "expires_at": datetime}}
        self._admin_cache: dict[str, dict] = {}
        self._admin_cache_ttl = 300  # 缓存5分钟

        # 群聊最后管理员发言时间 {group_id: datetime}
        self._last_admin_message_time: dict[str, datetime] = {}
```

关键方法：

| 方法 | 作用 | 缓存策略 |
|------|------|---------|
| `get_group_admins(event, group_id)` | 获取群内所有管理员/群主 ID | 5分钟 TTL，到期自动刷新 |
| `is_user_admin_cached(event, group_id, user_id)` | 判断用户是否为管理员（走缓存） | 使用缓存列表 |
| `is_user_admin(event, group_id, user_id)` | 判断用户是否为管理员（无缓存，精确查询） | 每次调用 `no_cache=True` |
| `record_admin_message(group_id)` | 记录管理员发言时间戳 | 直接写入内存 |
| `get_last_admin_time(group_id)` | 获取最后管理员发言时间 | 从内存读取 |
| `clear_cache(group_id=None)` | 清除缓存 | 全量或指定群 |

**注意**：`on_message` 中的在线检测使用 `is_user_admin_cached`（走缓存），执行 `/添加白名单` 等敏感命令时的权限验证使用 `is_user_admin`（精确查询）。

### ConfigManager — 决策逻辑引擎

文件：`handlers/config_manager.py`

核心方法 `should_enable_censor` 实现了完整的决策树：

```python
def should_enable_censor(group_id, last_admin_time) -> tuple[bool, str]:
    config = self._group_config.get(group_id)
    if not config:
        return (False, "未配置")  # 安全兜底

    # ── Tier 1: 未启用智能审查 → 全量审查 ──
    if not config.get("enable_auto_censor", False):
        return (True, "全量审查模式")

    # ── Tier 2: 在强制审查时间段内 → 强制开启 ──
    schedule = config.get("schedule_parsed")
    if schedule and self._is_in_schedule(schedule):
        return (True, "智能审查-强制时间段")

    # ── Tier 3: 管理员在线检测 ──
    no_admin_minutes = config.get("auto_censor_no_admin_minutes", 0)
    if no_admin_minutes > 0:
        if last_admin_time:
            elapsed = (datetime.now() - last_admin_time).total_seconds() / 60
            if elapsed >= no_admin_minutes:
                return (True, "智能审查-管理不在线")   # 超时 → 开启
            else:
                return (False, "智能审查-管理在线")    # 未超时 → 暂停
        else:
            return (True, "智能审查-管理不在线(无记录)") # 无记录 → 开启

    # 未设置在线检测，非强制时间段 → 开启
    return (True, "智能审查-非强制时间段")
```

### 主流程集成 — main.py

文件：`main.py:115-164`

```python
@filter.event_message_type(filter.EventMessageType.ALL)
async def on_message(self, event: AstrMessageEvent):
    group_id = str(event.get_group_id())
    user_id = str(event.get_sender_id())

    # 1. 检查群是否配置
    if not self._config_manager.is_group_enabled(group_id):
        return

    # 2. 获取群配置
    config = self._config_manager.get_group_config(group_id)
    no_admin_minutes = config.get("auto_censor_no_admin_minutes", 0)

    # ⭐ 步骤A: 若开启了在线检测，识别管理员发言并更新时间戳
    if no_admin_minutes > 0:
        is_admin = await self._admin_manager.is_user_admin_cached(
            event, group_id, user_id
        )
        if is_admin:
            self._admin_manager.record_admin_message(group_id)

    # ⭐ 步骤B: 查询最后管理员发言时间，决定是否跳过审查
    last_admin_time = self._admin_manager.get_last_admin_time(group_id)
    should_enable, reason = self._config_manager.should_enable_censor(
        group_id, last_admin_time
    )
    if not should_enable:
        return  # ← 核心：直接跳过后续所有审核流程，相当于"暂停"

    # ... 继续图片审核流程 ...
```

## 配置详解

### 配置项

| 配置项 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| `enable_auto_censor` | bool | `false` | 是否启用智能审查模式（开关） |
| `auto_censor_schedule` | string | `""` | 强制审查时间段，格式 `hh:mm-hh:mm` |
| `auto_censor_no_admin_minutes` | int | `0` | 管理员在线检测时间窗口（分钟） |

### 配置示例

**场景 1：严格模式 — 夜间强制审查，白天管理员在则暂停**

```json
{
  "enable_auto_censor": true,
  "auto_censor_schedule": "23:00-09:00",
  "auto_censor_no_admin_minutes": 30
}
```

```
23:00 ──────────────────────────────── 09:00 ──────────────── 23:00
│         强制审查（管理睡觉）         │    智能检测（管理在则暂停）    │
│          始终开启审查               │    管理30分钟有发言→暂停     │
│                                     │    管理30分钟未发言→开启     │
└─────────────────────────────────────┴─────────────────────────────┘
```

**场景 2：宽松模式 — 仅白天管理员在线时暂停**

```json
{
  "enable_auto_censor": true,
  "auto_censor_schedule": "",
  "auto_censor_no_admin_minutes": 15
}
```

```
全天（无强制时间段）
   管理15分钟内有发言 → 暂停审查
   管理15分钟未发言 → 开启审查
```

**场景 3：全量审查模式（默认）**

```json
{
  "enable_auto_censor": false
}
```

```
全天始终审查，不受管理员在线状态影响
```

### 时间段语法

| 格式 | 含义 | 示例 |
|------|------|------|
| `hh:mm-hh:mm` | 时间段 | `23:00-09:00` 夜间 23 点到次日 9 点 |
| 跨天 | 自动支持 | `22:00-08:00` 晚上 22 点到次日 8 点 |
| 空字符串 | 无强制时间段 | `""` 全天走在线检测 |

## 代码复杂度分析

| 维度 | 数据 |
|------|------|
| 核心决策方法体量 | 约 30 行（`should_enable_censor`） |
| 新增状态量 | 内存中一个 `dict[group_id → datetime]` |
| 额外 API 调用 | 零（管理员身份走缓存 `is_user_admin_cached`） |
| 对主流程侵入 | 仅在消息处理器最前面插入 ~15 行代码，`return` 后不影响后续逻辑 |
| 耦合度 | `AdminManager` 和 `ConfigManager` 之间仅通过 `datetime` 通信 |

## 最佳实践

1. **合理设置在线检测时间窗口**：建议 15-30 分钟。太短（<5 分钟）容易频繁开关；太长（>60 分钟）失去暂停意义
2. **强制时间段建议设置为管理员的睡眠时间**：如管理员是学生/上班族，可配合其作息设置
3. **结合禁言时长配置**：智能暂停期间若有违规，管理员事后可在管理群手动处理
4. **可与权限验证配合**：开启 `enable_admin_permission_check: true` 确保只有管理员能执行敏感命令

## 与"管理员违规不处罚"的区别

注意区分两个独立但互补的功能：

| 功能 | 触发条件 | 效果 | 配置项 |
|------|---------|------|--------|
| **智能审查-暂停** | 管理员在线（最近发言） | 完全跳过审核流程，不检查任何图片 | `enable_auto_censor` + `auto_censor_no_admin_minutes` |
| **管理员违规不处罚** | 管理员发送了违规图片 | 检查图片，仅通知不处罚 | 无配置项，始终生效（硬编码） |

即：智能暂停是**事前**的（不审），管理员豁免是**事后**的（审了但不罚）。

## 扩展思路

若需更精确的"在线"检测，可在当前被动推断基础上增加：

```
在线状态 = 被动推断（发言时间戳） OR 主动检测（可选扩展）
    ↓                                         ↓
 零成本，默认启用                      websocket 心跳 / 群活跃事件
                                      （需平台支持，可配置开关）
```

当前实现选择了纯被动方案，以保持跨平台兼容性和零额外开销。
